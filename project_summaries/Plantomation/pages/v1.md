# Plantomation V1 – 4-Channel Controller (ESP32)

[← Back to Plantomation](../plantomation.md)

The V1 controller is the first and currently working Plantomation board. It waters **up to 4 plants** with **one pump** and **four valves**, reads **four capacitive moisture sensors** and a **spill sensor**, and is configured through a web interface.

| | |
|---|---|
| **Revision** | Version 1.0, schematic dated 2023-11-24 |
| **Status** | Designed, ordered, assembled and tested |
| **MCU** | ESP32-WROOM-32, 240 MHz, dual core |
| **Supply** | 12 V DC, 3 A (JST-XH, silkscreen "12V") |
| **Outputs** | 1 × pump, 4 × valve, all 12 V, low-side switched |
| **Inputs** | 4 × capacitive moisture sensor (5 V supply, analog), 1 × spill sensor (3.3 V, analog) |
| **Storage** | SD card (SPI) + internal SPIFFS |

| **PCB** | 100 × 80 mm, 2 layers, 4 × M3 mounting holes |
| **Firmware** | PlatformIO, Arduino framework (`V1/Plantomation`) |

## 1. Hardware

### Block overview

| Block | Implementation |
|---|---|
| Controller | **ESP32-WROOM-32** module |
| USB | **USB-B** (Lumberg 2411 02), **CP2102N** USB-UART bridge, **USBLC6-2SC6** ESD protection, ferrite bead on VBUS, two **BC846** transistors for automatic reset/boot |
| VBUS jumper | 2-pin header "VBUS Enable" – lets the board be powered from USB for programming |
| 5 V rail | **L7805** in D-PAK on a **Fischer FK 244 13** SMD heatsink – supplies the moisture sensors |
| 3.3 V rail | **AMS1117-3.3** – supplies the ESP32, SD card and spill sensor |
| Valve drivers | 4 × **BSS138** N-MOSFET, 1 kΩ gate resistor, 100 kΩ gate pull-down, **LL4148** flyback diode |
| Pump driver | **DMG1012UW7** N-MOSFET with LL4148 flyback diode |
| Sensor inputs | RC-filtered (100 Ω / 1 nF) into ESP32 **ADC1** pins |
| SD card | **GSD090012SEU** socket with card-detect and write-protect switches |
| Status LEDs | 4 × 0805 LED, one per channel (labelled "State LEDs") |
| Buttons | **RST** and **BOOT** (CK PTS636) |
| Connectors | JST-XH 2.5 mm: 3-pin for sensors S1–S4, 2-pin for valves V1–V4, pump, 12 V and spill |

## 2. Firmware

### Structure

| File | Content |
|---|---|
| `main.cpp` | Setup, main loop, sensor reading, channel handling, pump control, logging, timer ISRs |
| `classes.h/.cpp` | `Wifi`, `Plant` and `SysConf` classes with JSON `load_config()` / `save_config()` |
| `server.cpp` | Wi-Fi start (station or access point) and ArduinoOTA |
| `web.cpp` | All HTTP routes (pages, settings, JSON data) |
| `config.h` | Pin definitions, file paths, calibration constants |
| `html/*.html` | Web pages, packed into `sites.h` by `html-save.py` before every build |
| `html/pictures.h` | Favicon |

### Boot sequence

1. Configure pins, switch the LEDs, prepare four hardware timers (one per channel for time control).
2. Mount SPIFFS. If an SD card is detected, mount it too.
3. Load `control.json`, `plant1–4.json` and `wifi.json` – from SD (and copy to SPIFFS) or from SPIFFS.
4. Start Wi-Fi. Station mode gets 2 s to connect, otherwise the board falls back to access-point mode.
5. In station mode: get the time from `pool.ntp.org` (UTC+1).
6. Start ArduinoOTA.
7. Start the web server task on **core 0**. The watering logic runs in `loop()` on **core 1**.

### Main loop

- **Every loop:** read all channels in moisture mode and the spill sensor. Each reading is the average of 10 samples taken 100 ms apart.
- **Every ~100 loops:** if there is no spill, handle each channel:
  - **Moisture mode:** water if the measured moisture is below the threshold.
  - **Time mode:** water if the channel timer has fired.

### Moisture scaling

$$
\text{moisture}\,[\%] = 100 - \frac{\text{ADC} - 1600}{(3400 - 1600)/100}
$$

3400 counts = dry (0 %), 1600 counts = wet (100 %). The constants `moist_dry` and `moist_wet` are in `config.h`. Calibration from the web page is planned.

### HTTP interface

| Route | Method | Purpose |
|---|---|---|
| `/` | GET | Control page |
| `/config` | GET | Configuration page |
| `/about` | GET | About page |
| `/initial` | GET | JSON: names, modes, thresholds, intervals, volumes of all channels |
| `/cyclic` | GET | JSON: system status + colour, pump rate, current moisture % (polled every 2 s) |
| `/conf` | GET | JSON: system status, pump rate, modes, debug and log level |
| `/ch1` … `/ch4` | GET | Save name, threshold, interval and volume of one channel |
| `/modes` | GET | Save the operating mode of all channels, enable/disable timers |

| `/wifi_set` | POST | Save Wi-Fi settings and restart |
| *anything else* | – | `418: I am a teapot!` |

## 3. Getting Started (from the technical note)

1. **Optional – prepare an SD card.** Format it as FAT32 and create the `config/` and `log/` folders. You can pre-fill the JSON files. Without an SD card, skip this step.
2. **Power up** the board with 12 V and let it boot.
3. **Connect.** If you configured Wi-Fi, open the IP address printed on the USB serial port. Otherwise join the network `Plantomation-XX-XX-XX` (password `Planto1!`) and open `http://4.3.2.1`.
4. **Configure.** On the *Configuration* tab set the channel modes, pump flow rate, log and debug level, and your Wi-Fi.
5. **Set up the channels.** Go back to *Control*, name your plants and set thresholds or interval + volume.

*"Congratulations, you are now done!"*

## 4. Troubleshooting (from the technical note)

*The spill acknowledgement via Boot0 and the empty-reservoir alarm are documented but not yet in the firmware – see [author notes](author-notes.md#2-documentation-vs-code-v1).*

| Problem | Solution |
|---|---|
| **Spill alarm** – all valves closed, pump off, all LEDs blink at 1 Hz | Dry up the spill, then reset the board or press **Boot0** to acknowledge |
| **Empty reservoir** – LEDs blink alternately | Refill the reservoir and press **Boot0** |
| **File system error** at boot | Set `FORMAT_SPIFFS_IF_FAILED` to `true`, upload, set it back to `false`, upload again |
| **JSON config corrupt** | Check the files on the SD card for typos. If it persists, empty the SD card – valid default files are created on the next boot |
