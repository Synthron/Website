# AGENTS.md

Instructions for AI agents and contributors working in this repository.

## Project Summary

This repository contains a personal project website built with **pure HTML, CSS and vanilla JavaScript**. See [`README.md`](README.md) for the full outline, data model, templating reference and todo list. Treat the core directives in the README as binding. If [`todo.md`](todo.md) exists, it tracks the remaining open work and records the decisions already made with the user. The multi-language setup is recorded in [`language.md`](language.md) (decisions L1–L32, work log, open owner tasks in Phase M20). The ham radio section is planned in [`radio.md`](radio.md) (decisions R1–…, open steps).

## Language

- **Site content and all UI text** (page text, buttons, labels, `title`, `meta description`, alt text) exist per language: **German** (`de`, default) and **English** (`en`). The content of a page is always in the language of its folder; UI texts come from `data/strings.json` (`{{t:key}}`).
- **Translations are written by the owner.** Do not invent or translate English (or other) site content unless the user explicitly asks. Create structure and clearly marked placeholders instead: `TODO` for project texts, `TODO_<German label>` for labels (navigation, strings, footer note), `TODO: …` for body text.
- **Code, comments, docs** (`README.md`, `AGENTS.md`, `todo.md`, `language.md`) and **commit messages**: **English**.
- Commit messages use [Conventional Commits](https://www.conventionalcommits.org/): `type: summary` with `type` one of `feat`, `fix`, `docs`, `perf`, `refactor`, `style`, `chore`; imperative summary, at most 72 characters; then a bullet list of the concrete changes.

## Hard Constraints

- Use only HTML5, CSS3 and vanilla JavaScript (ES2020+).
- The project is an npm project (Node.js ≥ 24). npm packages may be installed and used for the build and tooling; declare them in `package.json` (preferably as `devDependencies`). The “dependency-free” rule applies to the built site in `dist/`: it uses no tracking, no cookies and no external services. Runtime code in the browser stays vanilla.
- Do not set cookies, and do not use `localStorage`, `sessionStorage`, or `IndexedDB` for user tracking.
- Do not add third-party scripts, trackers, analytics, fonts, or CDN assets. The site must render with no external requests. **Only exception:** the vendored, self-hosted ESP Web Tools in `js/vendor/esp-web-tools/` (approved, see Protected Files).
- Content Security Policy: never write a CSP by hand. Every page gets it from `{{csp}}` in `partials/head.html`. Pages containing `<esp-web-install-button>` automatically get `style-src 'self' 'unsafe-inline'` (required by ESP Web Tools); never add `'unsafe-inline'` anywhere else.
- Use system font stacks only. Do not download web fonts.
- Keep the design minimal: no heavy shadows, gradients-for-decoration, or decorative animation.
- Every page must be responsive, starting at 320px width.

| `wwwroot/js/vendor/esp-web-tools/` | Third-party code. Never edit, reformat or lint it. Update only by replacing the whole folder with the `dist/web/` build of a newer ESP Web Tools release, then test the flasher. |

## Build and Templating

Commands: `npm install` (once after cloning and whenever `package.json` changes), `npm run build` (wwwroot → dist), `npm run serve`, `npm start` (both), `npm run clean`, `npm run create:project -- "Name" "Brief"`, `npm run create:afu -- "Name" "Brief"`. The full reference of includes, `{{tokens}}`, `@directives` and `@raw` is in [README → Build-time Templating](README.md#build-time-templating); do not duplicate it here.

- Never hard-code generated content (site name, year, footer note, email, nav, CSP, project titles/summaries/cards). Use the tokens, includes and directives.
- Every page `<head>` starts with `<!-- @include head -->` and adds only its own `meta description` and `title` (plus e.g. `robots` where needed). Use `{{name}}` in every `title` and `meta description`.
- Navs come from `data/nav.json` / `data/footer-nav.json`; never hard-code nav links.
- Wrap code samples that contain `{{…}}` or `<!-- @… -->` in `<!-- @raw -->` … `<!-- @endraw -->`.
- Browser scripts must not fetch content; everything is pre-rendered.
- If you add a token, directive or check, document it in `README.md` in the same change.

## Tooling Packages

The `devDependencies`, their jobs, planned scripts and config files are listed in [README → Tooling Packages](README.md#tooling-packages). Wiring them in is approved and tracked in README → Phase 6.

- Use the installed package for its job instead of hand-written code: `ajv` for data validation, `html-validate` for HTML rules, `eslint` / `stylelint` for JS/CSS rules, `sharp` for raster images, `svgo` for SVGs, `@playwright/test` for browser checks, `@lhci/cli` for Lighthouse.
- Run every tool through an npm script (`lint`, `lint:js`, `lint:css`, `lint:html`, `images`, `test:e2e`, `lighthouse`) with its config file in the repository root. Document new scripts and files in the README in the same change.
- Lint, never mass-fix: no `--fix` and no formatter over existing files without user approval. Fix findings by hand in the files you touch. If a rule flags many existing files, report it and ask whether to adjust the rule or fix the files.
- Exclude protected and generated paths from every tool: `wwwroot/js/vendor/`, `wwwroot/assets/firmware/`, `node_modules/`, `dist/` (only `html-validate` reads the built pages in `dist/`).
- `npm run build` and `npm run check` stay fast and offline; only `ajv` runs inside them. Playwright and Lighthouse run on demand against `npm run serve`, never inside `build` or `check`.
- Images: `sharp` writes new files next to the original and never deletes or overwrites originals; `svgo` optimises SVGs in place (git keeps the previous version). The page keeps its `alt` text; switch references to the WebP in the same change.
- No external services: Lighthouse CI uses `upload.target: "filesystem"` only; Playwright tests run against `localhost` and fail on any external request.
- New package: `npm i -D <name>` (PowerShell: `npm i -D '@scope/name'`), then add it to the README table. Nothing from a package may reach `dist/` or the browser runtime.

## Coding Standards

### HTML
- Semantic elements first (`header`, `nav`, `main`, `section`, `article`, `footer`).
- Exactly one `h1` per page.
- Attributes in double quotes; lowercase tags and attributes.
- Links to internal pages use relative paths (e.g., `projects.html` inside a language folder, or `{{langRoot}}projects.html`); shared partials use `{{root}}`. Links stay inside the page's language (exceptions: the language selector and footer entries with `lang`). The build fails on broken internal links.
- Every `img` has `alt` (empty `alt=""` only for purely decorative images).

### CSS
- Mobile-first: base styles target small screens; use `min-width` media queries.
- Breakpoints are defined in `css/responsive.css` only: `640px` and `960px`.
- Colours, spacing and type scale are defined as custom properties in `css/base.css`. Do not hard-code colours elsewhere.
- Use `rem` for font sizes and spacing; avoid fixed pixel widths for containers.
- Support `prefers-color-scheme` and `prefers-reduced-motion`.
- Class names: lowercase, hyphenated, BEM-light (e.g., `project-card`, `project-card__title`).

### JavaScript
- Vanilla ES modules only. No `var`; use `const` by default, `let` when reassigned.
- Each module exports functions and initialises on `DOMContentLoaded` via `js/main.js`.
- Handle missing DOM elements and malformed attributes; never throw uncaught exceptions.
- No `innerHTML` with unsanitised data; build nodes with `document.createElement` or use `textContent`. The build script must HTML-escape all data it inserts.
- No `document.cookie`, no storage APIs for tracking.

### Node scripts (`scripts/`)
- Node built-ins or npm packages declared in `package.json`; ES modules (`.mjs`).
- Match the existing style: single quotes, 2-space indent, semicolons, long lines allowed. Do not run a formatter over existing files; it would rewrite every line.

### Data
- `data/projects.json` must match the schema documented in `README.md`.
- Required fields: `id`, `title`, `summary`, `tags`, `status`, `date`, `links`, `image`, `featured`.
- `title`, `summary` and `tags` are objects keyed by language code; the default language is required, others are optional (`"TODO"` or a missing key hides the project in that language and the build warns). `id`, `status`, `date`, `links`, `image`, `featured` and `draft` are language-neutral.
- `id` values are unique, lowercase, hyphenated.
- `status` is one of the German keys: `in Arbeit`, `fertig`, `pausiert`, `veraltet`, `Konzept`, `abgebrochen`; the label per language is `strings.<lang>.status`.
- `tags` are lowercase and hyphenated (same rule as `id`), no duplicates per project and language; the lists of the languages are independent.
- `links.repo` / `links.demo` are `null` or an http(s) URL; `image` is a relative path inside `wwwroot/` (no `../`).
- `date` format: `YYYY-MM`.
- Each project needs a page `wwwroot/de/proj/{id}.html`; other languages use `<lang>/proj/{id}.html` or the mapped name from `data/pages.json`. The build fails without the default-language page.
- `strings.json`, `nav.json`, `footer-nav.json` and `site.footerNote` need an entry for every configured language; `data/pages.json` only lists pages whose file names differ.

## Workflow for Agents

1. Read `README.md` and this file before making changes.
2. Pick the work: do what the user asks. Otherwise take the next unchecked step in [`todo.md`](todo.md) (or, if there is no `todo.md`, the README todo list). Skip steps marked **User** and anything that needs real content from the user (texts, images, project data); ask instead.
3. When a step is completed, tick its checkbox in `todo.md` and, where one exists, the matching item in the README todo list.
4. Keep changes scoped: one step or concern per change. Do not refactor unrelated files.
5. When you create a file, add it to the README outline in the same change.
6. Verify every change (see Verification).
7. Do not commit, push or deploy unless explicitly asked. Never switch, create, merge, rebase or push branches unless asked; work on the currently checked-out branch.
8. End with a ready-to-use commit message in Conventional Commits format (see Language), even if no commit is being made.

## Verification

1. `npm run build` must exit 0. Fix every reported error.
2. Run `npm run check`, `npm test` and `npm run lint`.
3. For page or style changes: `npm run test:e2e` (without the Playwright browser: `$env:PLAYWRIGHT_CHANNEL='msedge'`). Manual check if needed: `npm run serve` (port 8000, `PORT` overrides), open the affected pages at 320px, 768px and 1280px width.
4. Browser DevTools (or `npm run test:e2e`): no console errors, no external requests in the Network tab, no cookies or storage entries.
5. For build refactors: compare `dist/` before and after (see Common Tasks).
6. Before a release: `npm run lighthouse` (accessibility and performance ≥ 95).

## Windows / PowerShell Notes

The main development machine runs Windows with PowerShell 5.1.

- Chain commands with `;`, not `&&` (`&&` inside npm scripts is fine).
- Quote scoped npm package names: `npm i -D '@eslint/js'`. A bare `@name` is PowerShell splatting and silently drops the argument.
- `Get-Content` without `-Encoding UTF8` shows UTF-8 umlauts as mojibake (`Ã¼`). That is a display issue, not a broken file; do not "fix" files based on it.
- Never write or edit files with `>`, `Out-File` or `Set-Content` (they change encoding and line endings); use the editor tools.
- Git may check files out with CRLF (`core.autocrlf`). Do not convert line endings of files you did not change.

## Definition of Done

- `npm run build` passes (plus `npm run check`, `npm test`, `npm run lint` and `npm run test:e2e`).
- HTML rules are enforced by the build checks and `npm run lint:html` (`html-validate`) where available; a manual check with the W3C validator (validator.w3.org/nu) is done occasionally, e.g. before a release, not for every change.
- No console errors in the browser.
- No external network requests and no cookies set.
- Keyboard navigable; visible focus styles.
- Matches the minimal design and directives in `README.md`.
- Checkbox ticked in `todo.md` / `README.md`.

## Things Agents Must Not Do

- Do not invent project data or page text, and do not translate site content on your own initiative. Use placeholders clearly marked as such (`TODO`, `TODO_<German label>`), or ask the user.
- Do not add tracking, analytics, or consent banners (there are no cookies to consent to).
- Do not replace the system font stack with custom or web fonts.
- Do not extend the build pipeline beyond its documented scope without user approval. npm packages for tooling are allowed, but nothing they produce may add tracking, cookies or external requests to `dist/`.
- Do not run `--fix`, formatters or bulk image conversions over existing files without user approval, and never upload test or Lighthouse reports to external services.
- Do not edit files in `dist/` or any other protected file (see Protected Files).
- Do not write long prose in code comments; keep comments short and technical.
