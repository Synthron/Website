# AO4 – 4-channel Analog Output (V2) – sub-page source

**Module type bits:** 011 (`DEV_AO` 0x60). **Address:** `0x60 + DIP(0–31)`. PCB: `hardware/pcbs/AO_V2` (one of the "major steps" improved in V2).

## Hardware
- **4 channels**, each selectable as **0…10 V (constant voltage, CV)** or **0…20 mA (constant current, CC)**. The CV/CC choice is made by a **relay per channel** (4× Omron G6K-2 DPDT signal relays with flyback diodes, driven by BC846 transistors).
- DAC: **MCP4728** (quad 12-bit I²C DAC, MSOP-10) → 12-bit hardware resolution. (The tech note quotes "16-bit" value range and 0.15 mV / 0.30 µA resolution; the DAC itself is 12-bit – describe it as "12-bit DAC, 16-bit register values". Verify before publishing exact resolution.)
- Output stage: **LM358** dual op-amps (4 packages U8–U11 = 8 op-amps, 2 per channel: voltage stage + current/V-I conversion), 100 Ω / 47 Ω output resistors, 270 pF compensation, 43 k/62 k/100 k scaling resistors, BAV199 clamp diodes to 24 V / GND2.
- **Galvanic isolation** between logic and analog side: **ADuM1250** isolated I²C isolator + isolated supply; the analog side runs on **+24 V external** with an **L78L05** 5 V regulator → **at least 15 V (24 V) with common analog ground must be supplied** to the module.
- Front: 4 LEDs (one per channel), showing the channel is active.
- Protection: SM6T36A TVS, PFRA 010 resettable fuse, ferrite, 1N4001 reverse protection on the 24 V input.
- Standard slave hardware (STM32F103C8T6, I²C1 to DAC, MAX485E, SN65HVD232, 5-bit DIP, AP1117-33).
- Simulation: `hardware/simulations/analog_out.asc` (LTspice).

## Software
- Registers `REG_CH1…REG_CH4` (0x4–0x7), **16-bit write** (LSB first), value 0…10000 corresponds to 0…10 V (or 0…20 mA in CC mode) on the CPU API (`synplc_write_analog_output(addr, ch, 0…10000)`).
- Conversion in firmware: CV: `dac = value / 2.5` (→ 0…4000), CC: `dac = value / 5` (→ 0…2000); all four values are written in one I²C transfer (`write_all`) roughly every 100 ms.
- Relay/mode status bits (`dac_stat`) select CC vs CV per channel; LEDs/relays on PA5–PA12.
- Read: only error register `0xF` implemented.
- Planned registers per tech note (not in firmware yet; register numbers copied as documented, note the tech note skips `0x8`):

| Reg | Function |
|---|---|
| `0x1` | Channel-enable register |
| `0x2` / `0x3` | Voltage / current channel 1 (16 bit) |
| `0x4` / `0x5` | Voltage / current channel 2 |
| `0x6` / `0x7` | Voltage / current channel 3 |
| `0x9` / `0xA` | Voltage / current channel 4 |
| `0xC` | Channel-status register |
| `0xD` | Channel-error register |
| `0xF` | Error register |

  These conflict with the firmware's `REG_CH1…4 = 0x4…0x7`; decide with the author before publishing.
- CubeMX: USART3 **1 MBaud** (interrupt driven), CAN 1 Mbit/s, I2C1 on PB6/PB7 to the DAC, relay control lines CC1–CC4 on PA5–PA8, channel LEDs PA9–PA12, DIR on PB12.
- Front panel: 4-LED cover (`Gehaeuse-front_led_4.stl`). PCB 100 mm × 77 mm.
