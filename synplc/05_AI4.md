# AI4 – 4-channel Analog Input (V2) – sub-page source

**Module type bits:** 010 (`DEV_AI` 0x40). **Address:** `0x40 + DIP(0–31)`. PCB: `hardware/pcbs/AI_V1` (STM32-based revision).

## Hardware
- **4 channels**, each measures **0…10 V** or **0…20 mA**.
- ADC: **ADS1115** (16-bit, I²C, TSSOP-10) – the tech note specifies **12-bit effective resolution**, ≈2.4 mV (10 V range) per step (note: the doc's "4.8 mA" for current is likely a typo for ≈4.8 µA; verify before publishing).
- Signal conditioning: **LM358** dual op-amps (4 packages = 8 op-amps, 2 per channel), 0.1 % precision resistor networks, RC filters (see `analog_in.asc` simulation), TLP291-4 optocouplers, BAV199 / TVS clamping, polyfuse and ferrite beads on the 24 V field supply.
- **Electrically isolated** from the system: **ADuM1250** I²C isolator; analog side supply via **L78L05** and **L78L10** regulators from external supply (needs external 24 V on the connector).
- Standard slave hardware (STM32F103C8T6, I²C1 to ADC on PB6/PB7, TIM1/TIM2, MAX485E, SN65HVD232, 5-bit DIP, AP1117-33). CubeMX CAN ≈ 750 kbit/s. PCB 100 mm × 77 mm; front panel: 4-LED cover.
- Simulation: `hardware/simulations/analog_in.asc`.

## Software
- Reserved register interface: `REG_CH1…REG_CH4` (0x4–0x7), 16-bit read; CPU API `synplc_read_analog_input(addr, ch, &value)`.
- **Firmware is only a CubeMX skeleton** (peripherals initialised: GPIO, CAN, I²C1, TIM1, TIM2, USART3; empty main loop). RS485 slave + ADC readout still to be written.
